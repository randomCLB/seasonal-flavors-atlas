# v1.1 时令抽签：实现与验收记录

基线：`f13172f0d7fd05027da00c5f0734838ecb7d7e45`，55 味。
本次更新首页节气主角分配、签文推荐标签与问卷、日历分享方式和详情首图规则；时令抽签仍是独立页面，主站导航排在“风味星图”前。

## 打开与测试

本地运行 `python3 -m http.server 8766 --directory dist`，访问 `http://localhost:8766/lottery.html`；网站发布后，也可从首页导航进入“时令抽签”。
原 v1 的“此刻当季”“山川来处”和“风味星图”继续保留。

运行 `node --test tests/lottery.test.cjs`，不需要安装 npm 依赖。
GitHub Actions 会运行逻辑与页面引用检查，再发布当前首页和时令抽签；旧预览地址同步指向同版内容。

## 已实现

- 五问：忌口排除、味道、质地、料理方式和尝新程度。不能识别的其他忌口阻止继续。
- 从下一个节气开始的六个完整时间段，跨年处理；按整段日期而非起始月份选候选。
- 食材、产地、配方一起选择；同一食材不重复，使用增广匹配优先保证可满足的槽位数量，再在合格方案中兼顾口味与品类。
- 锁住指定食材、只换一签、重抽未锁定的签、原站详情与复制采购词。
- 点一次打开手机系统分享菜单，将六节气 `.ics` 交给用户选择的日历应用；不再展示日期、时区和逐项勾选表单。浏览器不支持文件分享时才回退下载 ICS。
- 每个事件包含采购搜索词、做法、保存、注意事项和详情链接；没有用户答案或过敏档案。
- 稳定 UID、修订序号、UTC 时间、UTF-8 字节折行、CRLF、独立事件与 DISPLAY 提醒。
- 默认不持久保存，主动勾选后才写本地存储，支持清除。没有账号、模型调用、追踪、定位或日历读取。

## 推荐池与限制

55 味都有按 v1 **声明配方**整理的标签，配方指纹变化会停止推荐并要求复核。这不是临床/过敏认证。
可选配料也参与排除；成分不明的通用油、酱、汤底使用保守的 `uncertain` 标签。
不自动发明替代菜谱，纯素用户因此可能看到较少候选，优于静默删除配料或放宽限制。

自动推荐暂缓三项：猴腿菜（身份资料待核）、盐池黄花菜（现有菜谱主用干品）、珠海禾虫（潮汛与农历条件需另审）。其余 52 味并非每次都符合当前节气或偏好。

时令按原站证据和产地记录过滤；羊肚菌二月、宁海白枇杷五月采用下旬保守起点。没有新增“最佳成熟日”的精度承诺。未来食单不是库存预报，不承诺附近有货或三天送达。

## 已执行的测试

- Node 22：41 项测试通过，包括偏好严格命中、多选不限两项、成菜图条目与文件校验、页面元素引用、12 个月 × 6 组限制 × 3 档尝新程度扫描、跨年、配方排除、单签替换和日历文件格式。
- Playwright CLI 本地页面检查：24 个节气主角均不重复且都出现在下方列表；390×844 手机视口；五问真实点击；可同时选择三个味道及多项质地和做法；可生成六节气食单。分享菜单分支用浏览器替身检查，未在 iOS 或 Android 真机上确认日历应用导入。

**浏览器验证边界：** 页面通过本地 HTTP 在 Chromium 会话中打开。移动尺寸是模拟视口，不是真机；系统分享流程不能由桌面浏览器证明，仍需用真实手机确认分享目标及日历应用的保存提示。

## 发布前仍须核验

- iOS Safari、Android 常用日历：系统分享菜单里是否出现可用日历应用、导入后的提醒是否保留。网页无法替用户确认最终保存状态。
- 推荐配方标签与原站时令资料的人工内容复核。
- 系统分享仍传递一个标准 `.ics` 文件；日历应用需要用户确认保存。它不是静默写入或自动订阅。
