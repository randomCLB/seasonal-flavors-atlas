基线：`f13172f0d7fd05027da00c5f0734838ecb7d7e45`，55 味。

## 打开与测试

本地运行 `python3 -m http.server 8766 --directory dist`，访问 `http://localhost:8766/lottery.html`；网站发布后，也可从首页导航进入“时令签”。
原 v1 的“此刻当季”“山川来处”和“风味星图”继续保留。

运行 `node --test tests/lottery.test.cjs`，不需要安装 npm 依赖。
GitHub Actions 的新检查只运行测试并附上静态预览包，不部署 Pages。
浏览器检查可运行 `python scripts/test-lottery-browser.py`，需要 Playwright 和 Chromium，可通过 `CHROMIUM` 指定可执行文件。设置 `FENGWU_OFFLINE=1` 时使用完全内联的离线页面，需要 Pillow。

## 已实现

- 五问：忌口排除、味道、质地、料理方式和尝新程度。不能识别的其他忌口阻止继续。
- 从下一个节气开始的六个完整时间段，跨年处理；按整段日期而非起始月份选候选。
- 食材、产地、配方一起选择；同一食材不重复，使用增广匹配优先保证可满足的槽位数量，再在合格方案中兼顾口味与品类。
- 锁住指定食材、只换一签、重抽未锁定的签、原站详情与复制采购词。
- 采购日历预览、调整尝鲜日期/询货提前量/时间/时区、单项勾选、整份 ICS 导出。
- 每个事件包含采购搜索词、做法、保存、注意事项和详情链接；没有用户答案或过敏档案。
- 稳定 UID、修订序号、UTC 时间、UTF-8 字节折行、CRLF、独立事件与 DISPLAY 提醒。
- 默认不持久保存，主动勾选后才写本地存储，支持清除。没有账号、模型调用、追踪、定位或日历读取。

## 推荐池与限制

55 味都有按 v1 **声明配方**整理的标签，配方指纹变化会停止推荐并要求复核。这不是临床/过敏认证。
可选配料也参与排除；成分不明的通用油、酱、汤底使用保守的 `uncertain` 标签。
不自动发明替代菜谱，纯素用户因此可能看到较少候选，优于静默删除配料或放宽限制。

自动推荐暂缓三项：猴腿菜（身份资料待核）、盐池黄花菜（现有菜谱主用干品）、珠海禾虫（潮汛与农历条件需另审）。其余 52 味并非每次都符合当前节气或偏好。

时令按原站证据和产地记录过滤；羊肚菌二月、宁海白枇杷五月采用下旬保守起点。没有新增“最佳成熟日”的精度承诺。未来食单不是库存预报，采购方式影响询货节奏，不承诺附近有货或三天送达。

## 发布前仍须核验

- iOS Safari + 系统日历、Android + 常用日历应用：文件接收、中文、时区和提醒是否保留。
- iOS Safari + 系统日历、Android + 常用日历应用：文件接收、中文、时区和提醒是否保留。
- 推荐配方标签与原站时令资料的人工内容复核。
- ICS 为一次性文件导出；不会自动写入用户的日历，也不是订阅。重新导入可能产生重复。
- Google OAuth 批量写入与 iPhone 个人订阅尚未实现。

## 参考规范

- RFC 5545：https://www.rfc-editor.org/rfc/rfc5545
- Google 导入说明：https://support.google.com/calendar/answer/37118?hl=zh-Hans
- Apple Mac 日历导入：https://support.apple.com/zh-cn/guide/calendar/icl1023/mac

ICS 是一次性快照，不是订阅。再次导入可能产生重复。推荐使用专用日历，并在重导前核对或删除旧安排。
