# v1.1 时令抽签：五问修订

按用户试用反馈，本次取代原先的“口感 / 做饭投入 / 在哪买 / 熟悉程度”问法。

## 五问
1. 忌口：不愿吃或需要避开的，先作硬排除；仍核对主料、配料和可选配料。
2. 味道：酸、甜、苦、辣／辛、咸、鲜，可多选，或都可以。
3. 质地：清脆爽口、软糯绵密、柔嫩细滑、弹韧有嚼劲、多汁水润，可多选，或都可以。
4. 料理：鲜食凉拌、快炒煎炒、清蒸、水煮焯熟、汤羹炖煮焖烧，可多选，或都可以。不再询问技术水平或采购地点。
5. 猎奇程度：口味优先、带点特别、大胆猎奇。不推测用户吃过什么。

## 推荐规则
`lottery-senses.js` 依据已有55条食材与菜谱描述，独立记录食材味道、调味后味道、准备状态下的质地、料理和可描述的外形／香气／质感特点。元数据有源字段指纹；资料变更后不再使用过期的偏好得分。

硬排除、时令、产地与去重逻辑保留。每个已选择的偏好组都必须命中至少一项：味道可命中食材本味或该做法中的调味，质地和料理须命中对应标签；未命中时不推荐该食材，候选不足就留白。匹配项用于排序，猎奇仅给予明确特点一个有上限的额外权重。不按陌生程度、价格、地区或风险给食材评级，不启用原来暂停推荐的词条。

例如藕带本身清甜、脆；酸辣来自当前菜谱，只有选择了酸或辣／辛，藕带才会作为味道命中项，并在理由中说明调味来源。

采购默认提前3天询货，不是保鲜期或物流承诺。点击一次打开系统分享菜单并传递整份 ICS；用户选择日历应用并确认保存。若浏览器不支持分享文件，回退到下载 ICS。

## 旧记录
保存结构升级为schema 2。不把旧字段套入新问题，不静默删除旧食单；提示重新答题，用户主动保存新食单或清除时才替换／删除。日期、换签、锁签及导出逻辑保持。

## 验证
- Node：40项测试通过，含无限多选、每组偏好严格命中、12个月 × 6组限制 × 3档猎奇的216组扫描。
- Playwright CLI 已在本地 HTTP 页面实测多选及生成结果；手机尺寸为模拟视口。系统分享流程用浏览器替身覆盖，日历目标和保存提示仍需 iOS／Android 真机确认。
- 时令抽签通过首页导航进入，v1 原有食材、地图与浏览内容保持原样。系统分享减少了操作步骤，但网页无法静默写入日历；实际添加结果取决于用户选择的日历应用。

本文件取代原实施记录中的问卷与评分说明；其他原有边界仍适用。
