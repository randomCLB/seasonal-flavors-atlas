# v1.1 时令签：五问修订

按用户试用反馈，本次取代原先的“口感 / 做饭投入 / 在哪买 / 熟悉程度”问法。

## 五问
1. 忌口：不愿吃或需要避开的，先作硬排除；仍核对主料、配料和可选配料。
2. 味道：酸、甜、苦、辣／辛、咸、鲜，最多两项，或都可以。
3. 质地：清脆爽口、软糯绵密、柔嫩细滑、弹韧有嚼劲、多汁水润，最多两项，或都可以。
4. 料理：鲜吃／熟后凉拌、快炒、清蒸白灼、汤羹炖煮，最多两项，或都可以。正式选项见页面；不再询问技术水平或采购地点。
5. 猎奇程度：口味优先、带点特别、大胆猎奇。不推测用户吃过什么。

## 推荐规则
`lottery-senses.js` 依据已有55条食材与菜谱描述，独立记录食材味道、调味后味道、准备状态下的质地、料理和可描述的外形／香气／质感特点。元数据有源字段指纹；资料变更后不再使用过期的偏好得分。

硬排除、时令、产地与去重逻辑保留。味道、质地和料理各自计分；猎奇仅给予明确特点一个有上限的额外权重，随机噪声不随猎奇档位增加。不按陌生程度、价格、地区或风险给食材评级，不启用原来暂停推荐的词条。

例如藕带本身清甜、脆；酸辣来自当前菜谱，推荐理由会说明调味来源。没有对应偏好的候选仍可作为另一种选择，但说明不完全匹配；不会宣称匹配率。

采购默认网购询货，提前3天作为可编辑计划值，不是保鲜期或物流承诺。ICS仍为一次性导出。

## 旧记录
保存结构升级为schema 2。不把旧字段套入新问题，不静默删除旧食单；提示重新答题，用户主动保存新食单或清除时才替换／删除。日期、换签、锁签及导出逻辑保持。

## 验证
- Node：37项测试通过，含12个月 × 6组限制 × 3档猎奇的216组扫描。
- Chromium：55项离线浏览器检查通过，桌面1440×1000、手机390×844；覆盖五问顺序、多选上限、返回保留、推荐、留签、换签、ICS真实文件下载、保存／清除和旧记录提示。
- 浏览器受运行环境导航限制，使用精确源脚本内联、仅展示压缩图片与内存Storage测试替身。这不是线上浏览器、持久存储、iOS／Android真机或系统日历验证。
- 时令签通过首页导航进入，v1 原有食材、地图与浏览内容保持原样。日历采用 ICS 一次性导出，实际写入和提醒效果取决于用户的日历应用。

本文件取代原实施记录中的问卷与评分说明；其他原有边界仍适用。
